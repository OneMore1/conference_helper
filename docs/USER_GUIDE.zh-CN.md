# 用户手册

适用版本：0.1.0。技能名称：`conference-helper`。

可以从一句大概方向开始；有方案、结果或稿件时，也可以直接交给 agent 处理本轮任务。
没有文件时，你在对话中描述的方向就是输入。数据、算力和时间条件可以逐步补充，未知项保留未知。
可以从分析结果、核对作业、修改一节或回复审稿直接开始，不必从选题走完整套流程。

## 1. 下载哪一个包

| 文件 | 用途 |
|---|---|
| `conference_helper-v0.1.0-source.zip` | 推荐首次安装和升级使用；包含安装器、完整说明、示例及配套命令。 |
| `conference-helper-v0.1.0.zip` | 仅含独立 Skill，适合已经知道宿主技能目录位置的人手动安装。 |

两种包的技能内容相同。源码包不需要 GitHub 登录或 Git；同批分发的 `SHA256SUMS.txt` 可用于核对 ZIP 完整性。
手动安装独立包时，把整个 `conference-helper` 文件夹放入目标项目的 `.agents/skills/`，保留所有子目录和许可文件。
已有安装时，建议使用源码包的备份升级命令，避免手动混合新旧文件。

## 2. 安装到你的研究项目

需要 Python 3.10 或更新版本，以及能够读取项目文件的 Codex。
Python 用于安装和可选的配套命令；研究判断与写作由 agent 完成。

先把源码 ZIP 解压到较短目录，例如 `C:\Tools\conference_helper`。
确认其中直接包含 `tools`、`skills` 和 `docs` 文件夹；不要把目录多嵌套一层。
研究项目另放，例如 `D:\Research\my-paper`。在 PowerShell 中运行：

```powershell
python --version
python "C:\Tools\conference_helper\tools\install_skill.py" --project "D:\Research\my-paper"
```

把 `--project` 后的路径替换为**你的研究目录**，不是源码目录。
安装成功会输出 `"status": "installed"` 和安装路径：

```text
D:\Research\my-paper\.agents\skills\conference-helper\SKILL.md
```

安装器复制 Skill 文件，不会初始化研究状态、运行实验、联网登录或安装 Python。
它不会修改注册表或系统设置。已有同名 Skill 时会停止，升级方法见第 7 节。

在 Codex 中打开 `D:\Research\my-paper`，新建对话，输入 `$conference-helper` 调用。
若未发现技能，先核对安装输出中的路径，再向 agent 提供该路径下的 `SKILL.md`，让它读取并按要求执行。
其他宿主的技能发现方式以其自身说明为准。

## 3. 第一条请求：一个方向或一个具体任务

### A. 只有方向：明确要研究的问题

~~~text
使用 $conference-helper。
我想研究一个 fMRI 基座模型方向的工作，目前只有大概方向。
请比较切入点，推荐一个具体问题，说明理由、未知项和最小验证。
先简短讲清楚，不启动实验。
~~~

第一轮应得到值得比较的问题和推荐理由，而不是要求你准备完整项目文件。已知数据、目标任务、时间或算力可以补充；不知道就保留未知。文献未核实时不能把候选问题称为研究空白。

接着可以说“采用这个问题，继续深化一个解法”或“直接形成最小实验计划”；主线已经确定时直接深化。

### B. 模型已设计：判断还缺哪些证据

~~~text
使用 $conference-helper。
我已经完成模型设计，后续还需要增加哪些 ablation？
读取我的设计说明和已有结果：[文件或粘贴内容]。
请把论断对应到缺口和对照，说明公平比较条件、结果判定和优先级。
已有证据可回答的部分直接复用，不启动实验。
~~~

应得到一张有依据的优先表：每项对照为什么需要、改变什么、保留什么、结果不好时如何解释。尚未提供的部件不能被虚构；删除模块掉点也不能直接写成机制已经证明。
模型设计完成与实验完成分别判断。补充也可以是重分析、澄清方法或缩小论断。

### C. 已有结果：组织文章的论证

~~~text
使用 $conference-helper。
如何把我们的结果整理成一篇文章？
读取方法、结果表与图：[文件或粘贴内容]。
请给推荐主线、论断与图表对应、章节提纲和一段有依据的示范文字。
保留负结果，把证据缺口放独立备忘录。
~~~

应得到面向当前结果的文章结构与实际文字，不能只返回通用章节名称。有些实验尚未完成时，继续写已有证据支持的部分；暂未支持的机制或泛化论断另行处理。

三个入口可独立使用，不是必经的三轮确认。[完整合成教学案例](../skills/conference-helper/examples/research-workflow-cases.md)展示每类输入、判断理由和交付。
默认在对话中回答；需要保存文件时指定格式与位置。文献为这些研究任务提供依据，本技能没有独立的论文解读入口。

## 使用研究 Tips

Skill 会根据当前任务选择[研究 Tips](../skills/conference-helper/references/review-tips.md)：选题时明确贡献与近邻差异，补消融时识别部件作用和竞争解释，写作时核对指标、图表与结论范围。
可以直接加一句“结合原研究的 Tips，指出本轮最值得改的一处，并给出具体改法”。不需要记住 Tip 编号或模式名称。

Tips 是原文启发和本项目的操作映射，不是录用概率模型。它们不要求固定模块数量，也不会把所有检查都变成必做实验。

## 4. 其他常用请求

按本轮任务提供直接相关的材料即可。

**分析已有结果**

```text
使用 $conference-helper。
读取 project-notes.md、results.csv 和 protocol.md，核对结果支持哪些结论。
请给出可核算的描述性汇总，区分已支持、尚不支持和仍不确定的论断；
引用具体文件及行列，保留负结果，并建议一个最有价值的下一步。
只读材料，不启动实验，不修改原稿或状态。
```

**核对执行日志**

```text
使用 $conference-helper。
读取 config.json、runs/ 下的日志和已有输出，核对这批作业完成到哪一步。
逐项区分准备完成、已启动、运行中、失败和训练/评估完成；
核对方法、数据版本、seed 和预期输出，不把旧汇总当作当前批次结果。
说明可用结果、能否开始写最终 Results，以及下一步，并引用具体文件。
只读，不启动、重启或修复作业，不修改稿件或状态。
```

**只改 Methods**

```text
使用 $conference-helper。
依据 protocol.md 和 config.json，只修改 draft.md 中的 Methods。
统一方法描述，修正有明确依据的不一致；保留研究方向、结果数字和其他章节。
直接给出该节修订稿；无法从材料确认的细节放入独立编辑备忘录，不编造。
本轮不写回原文件，不启动实验。
```

**跨会话接续**

```text
使用 $conference-helper。
继续这篇论文：先读 handoff.md，上一轮结果为 results-v1.csv，新材料为 results-v2.csv。
本轮只核对新材料影响哪些旧结论；保留仍成立的部分，不重新选题。
请引用版本与文件位置，说明完成项、未决项和一个推荐下一步。
只读原稿及已有状态，把本轮结论直接回复在对话中。
```

需要实际改文件时，把边界改为具体授权，例如“将修订稿另存为 Methods-revised.md，不覆盖原稿”。
语言、篇幅、标记改动等要求可以一起写入请求。

## 5. 它能自动做什么，哪些还需要你提供

agent 可以根据已读取的材料定位进度、整理结果、追踪论断依据、修改指定文本、提出补充建议，并准备审阅或投稿清单。
它会区分项目整体进度、本轮任务和可并行工作；部分实验未完成时，已有结果仍可先分析。

研究构思可以从自然语言方向开始；对已有结果、执行状态或稿件事实作出判断时，需要能够访问的真实材料，以及会影响结论的版本、划分、指标含义和比较设计。
结果表、旧稿或日志互相矛盾时，需要核对具体内容；仅有文件名、checkpoint 或“完成”摘要不能代替执行证据。
日志只能证明记录中的状态；要判断作业此刻是否仍在运行，还需要有权限的实时查询。

联网检索、远程执行、绘图和编译取决于宿主工具及授权，安装 Skill 不会增加这些能力。
上传私人材料、启动高成本实验、发送邮件或实际投稿需要明确授权。
agent 不应编造缺失结果、引用或方法细节；科学解释、引用支持度和最终投稿内容仍需作者复核。
章节写完不等于全文定稿，投稿包准备好不等于已经提交。

验收交付时看四点：是否完成指定任务；关键事实能否定位；是否遵守范围；下一步是否说明目的和停止条件。
判断不对时，直接指出正确材料或版本，让 agent 重查受影响的部分，无需先修改内部字段。

## 6. 跨会话记录与配套命令是可选项

短任务直接在对话中交付即可。希望下次接续时，可以授权 agent 新建 `handoff.md`，记录材料版本、完成项、未决项和下一步。
长期项目也可以要求 agent 整理持久化状态；先读材料、再登记进度，不要求你手填 JSON。
具体操作见 [进阶命令](QUICKSTART.zh-CN.md)。

配套 CLI 可以从短的源码目录调用，将你的研究目录作为参数，无需把研究材料搬入源码仓库。
例如，**已有持久化工作区**时可查询其记录：

```powershell
python "C:\Tools\conference_helper\skills\conference-helper\scripts\workflow.py" status "D:\Research\my-paper"
```

当前版本的安装器和配套 CLI 在内部处理研究目录、输入记录等合法的普通 Windows 长路径；这些参数直接填写普通路径即可。
Python 自身仍可能在执行前拒绝打开过长的脚本入口，因此按上面的方式从短源码目录调用 CLI，研究目录可以保持原位。
这不等于任意宿主都能原生发现或读取任意长路径中的 Skill；宿主扫描、解压工具和外部程序仍有各自边界。
遇到宿主发现问题，先检查实际安装位置；必要时使用较短的项目路径，或按宿主要求选择用户级安装。
安装选项 `--user` 和 `--destination` 见 [进阶命令](QUICKSTART.zh-CN.md)；初次使用建议项目安装。

## 7. 升级与简单排错

将新源码包解压到短目录，然后对同一个研究目录运行：

```powershell
python "C:\Tools\conference_helper\tools\install_skill.py" --project "D:\Research\my-paper" --backup-existing
```

旧 Skill 备份在扫描目录之外的 `.agents/skills-backups/`，具体位置见输出的 `backup` 字段。
保存该路径；升级 Skill 不会重建研究材料或自动迁移项目记录。
需要恢复时，先把当前 Skill 保存在扫描目录之外，再将备份放回原来的技能目录，避免混合版本。

| 问题 | 先做什么 |
|---|---|
| `python` 不可用或版本过旧 | 安装 Python 3.10+；也可用 `py -3 --version` 检查已安装版本，合适时将命令中的 `python` 换为 `py -3`。 |
| 提示找不到安装器 | 检查解压后的目录层级，确认 `tools/install_skill.py` 存在；使用完整路径，带空格的路径加双引号。 |
| 提示找不到项目或输入文件 | 核对实际路径、盘符和文件版本；不要把示例路径原样当作自己的项目。 |
| `Skill already exists` | 确认目标目录正确；需要升级时加 `--backup-existing`。 |
| 安装完成但 Skill 未出现 | 在目标研究项目开启新对话，核对输出路径下的 `SKILL.md`；必要时直接提供入口路径。 |
| 长路径报错 | 先将源码包解压到短目录，再用完整命令调用；区分报错来自安装器、宿主还是解压工具，保留原报错供排查。 |
| 结果或状态与新材料不一致 | 指定最新依据，让 agent 只重查受影响的结论；不要直接沿用旧汇总。 |
| 无法联网、绘图或编译 | 先完成现有工具能做的部分，明确哪些核验还未执行。 |

想先体验一轮，可按 [TinyShapes Demo](../examples/tiny-shapes/README.md) 操作；其中材料和数字均为合成教学示例。
按需教学：[从问题到计划](../skills/conference-helper/examples/problem-to-plan.md) 适合早期研究，把问题、最近邻差异和证据缺口整理为研究计划。
[从证据到写作](../skills/conference-helper/examples/evidence-to-writing.md) 适合 Introduction / Results 的论证改写，将已有证据与可支持的论断对应起来。
