# 分析实验：由真实结果更新认识（本包扩展）

## 开始
读取原始/汇总结果、字段字典、代码或统计日志、实验设计与用户要求。
只有截图时说明可读到的精度；没有可计算数据时输出分析计划或定性核对，不编造统计数值。
识别样本量、数据粒度、独立统计单位、缺失、重复、失败运行、指标方向和版本。
研究设计决定统计单位；不能将窗口、帧、重复扫描或交叉验证折机械地当作独立被试。

## 分析顺序
先描述完整结果与失败情况，再检查主比较，随后是机制/消融、稳健性、异质性和外部验证。
具体检验依据设计和用户锁定方案选择，不使用跨任务统一的显著性通行证。
用户明确先看未校正探索性 p 时保留该视图，标明探索属性和比较范围，不偷偷改变主分析。
适用时记录效应量、区间估计和不确定性，而不只记录 p 值。
检查重复搜索、测试集泄漏、调参后重复测试和选择性报告；保留合理的负结果。
新分析应写明是 planned / amended_before_execution / post_hoc，不重写既有计划历史。

## 推论
每个结果关联：问题 → 对照 → 实际观察 → 支持程度 → 替代解释 → 适用范围。
区分“性能变化”“对干预敏感”“机制被证明”“可推广”，不能互相替代。
没有显著差异不是等效证明；相关不自动成为因果；训练集改善不等于泛化。
把真正用到的统计方法与版本记入分析记录；涉及专门方法时查阅原始方法/官方文档。

## 产物
有持久化工作区且允许写入时保存 artifacts/analysis_report.md 并更新 evidence_ledger.json；临时或只读分析在回复中或用户明确指定的新输出位置交付，不要求先创建状态文件。
涉及计算时输出可核算表格及计算口径，必要时附可复现代码。
支持/反对/不确定的论断都保留。在证据不足处识别缺口，不能凭润色把假设写成发现。
完成意味着当前结果得到适当核查与解释，不意味着所有假设都得到支持。
