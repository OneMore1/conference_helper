# 把研究思路与证据讲清楚

用于解释用户自己的研究问题、模型设计、消融取舍或文章论证。借鉴从具体情境出发、解释关键改动、检查证据与边界的路线；当前产品不设独立论文解读功能。

## 围绕本轮问题展开
只有方向时说明具体问题、推荐理由、未知项和最小验证；已有模型时解释各项对照为何必要；已有结果时说明这些证据怎样组成文章。按 [三种研究入口](12-research-entrypoints.md) 交付，不强制每次走完整个流程。

把关键判断的理由放在对应建议旁边：哪个观察促使提出问题，哪个假设支持当前设计，哪个对照能区分竞争解释，哪个结果使论断需要收窄。资料没有提供这些依据时保留未知，不编造研究者真实动机或发现过程。

机制不直观时可用合理基线与小实例解释中间量，交代简化和失效条件。公式只在有助于判断时使用，并定义关键量。算术例子验证操作，不能替代独立任务指标或科学机制证据。

## 交付以任务为主
默认在对话中回答，篇幅按请求。只有方向时先给紧凑建议；明确要求实验方案或文章结构时完成相应交付。卡片、固定字段与 JSON 是辅助，不作为用户前置作业。

需要可保存文字时按用户要求提供 MD 等文档。需要比较参数、追踪状态或展示机制时，可按要求提供图或 HTML；不把格式选择作为继续研究的门槛。独立案例见 [方向—消融—成文](../examples/research-workflow-cases.md)。

HTML 若称为离线/自包含，必要资源不得依赖远端请求；数值标明来源，默认状态可读、键盘可操作、窄屏可用。实际核对计算、端点、失效与恢复；没有浏览器验证时如实说明。公开仓库使用相对资源路径，回复中的本地文件链接遵循宿主要求。

## 证据与范围
引用当前判断所需的文献和材料，记录版本及位置；论文陈述与实现有冲突时分别呈现，不能用其中一个版本无条件覆盖另一个。文献核查用于定位自己的问题、设计对照和支撑写作。

所有示意数值与拟做实验明确标记。已有方向不重开，缺实验不自动阻止有证据部分的写作。用户未要求长期记忆或改技能默认规则时，不因单次反馈自动写偏好日志或修改配置。
