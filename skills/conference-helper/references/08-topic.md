# 选题：确定研究什么（本包扩展）

## 任务与边界
从用户方向、资源和已观察现象出发，确定值得回答的具体问题及适用范围。
topic 回答“研究什么、为什么值得研究”；机制如何实现、为何可能有效及如何区分解释，交给 [构思](01-ideation.md)。
用户已确定具体问题或主线时保留其选择；宽泛方向可以收窄成问题，不把细化范围变成重新选题。
自然语言、已有稿件或结果都可作为输入，不要求先建立工作区或填写问题卡。

## 工作流
1. 将宽泛方向缩小成可检验问题：研究对象、任务、适用条件、现有方法的实际不足，以及需要获得什么能力或认识。
   “模型 X 用于数据集 Y”需要进一步说明真实瓶颈；问题可接受负答案，不以预期提升定义其价值。
2. 说明科学或方法价值，并核对数据、时间、计算、测量与评价条件。
   未知资源保留未知；区分已有材料、计划获得的材料和当前无法满足的条件。
3. 检索最近相关原始文献并阅读关键正文；记录来源、日期、阅读位置和已解决部分。
   用最近邻明确问题边界；零结果或阅读覆盖不足保持 `insufficient_search`，不把未查到等同于空白。
4. 需要作者比较时，通常保留 2–3 个有实质差异的候选；已有选择时深化一个，不为了数量编造方向。
   比较问题价值、最近邻、所需数据、最低区分观察、资源约束和主要不确定性；此处的最小实验用于判断问题能否回答，详细机制对照在后续阶段展开。
5. 按需讨论会议适配，依据当年官方范围和相关作品；不输出录用概率，不把模式频率当规则。

按 [研究 Tips](review-tips.md) 的 T1/T4/T6，把候选写成具体贡献设想、最近邻差异和可证伪观察。没有可核实依据时保留候选性质，不根据样本模式构成推荐“最高中稿率路线”。

## 输出与交接
交付问题卡：问题一句话、价值、适用边界、最近邻已解决部分、目标观察、资源依据和未决事项。
同时说明依据与取舍，例如为何收窄对象、保留某项约束或暂不覆盖另一场景；没有实际观察时用假设语气。
作者已选定且问题可明确表达和检验时，可将 research_question 记为完成；退出标准不是已有“好看的结果”。
尚未作出的选择保留待定，不登记成作者决定，不重复询问已有决定。
临时任务在回复中交付；有持久化工作区且允许写入时，可保存 artifacts/problem_card.md。
将已定问题及约束交给构思，构思阶段继承问题并提出解法；选题完成不代表新颖性已核实或实验已完成。
完整人工教学示例见 [从问题到最小计划](../examples/problem-to-plan.md)，可按需借鉴交接方式。
