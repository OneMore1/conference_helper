# 01 构思：承接已定问题，提出可区分的解法

## 输入与边界
继承用户已确定的问题、适用条件、目标能力和资源约束；可来自自然语言、已有稿件或问题卡，不要求先填表。
topic 回答“研究什么、为何值得研究”；本阶段回答“怎样解决、为何可能有效、怎样区分解释”。
已定主线不重新选题。问题尚有局部含糊时，只澄清会改变机制或预测的条件；需改变主问题时说明依据，不能把建议当作作者决定。
代表论文、已有观察、作者指定的解法和已确认结果作为输入，分别标明来源；已有证据与待验证解释分开。
缺少会议年份仍可构思，但不能提供当年投稿合规结论。

## 工作流
1. 用一句话继承目标：在已定设定下，需要解决哪个具体瓶颈，什么观察才算目标能力出现。
   不把“在数据集上换用模型 X”直接当作机制解释，也不改写问题以迎合某种创新模式。
2. 写清核心操作及其作用链：改变什么信息、约束、表示、测量或推断步骤；它如何影响瓶颈，再如何影响独立结局。
   method / diagnostic / empirical / theory / dataset / systems 用于描述贡献性质，不替代具体操作。
3. 列出决定解释成立的关键假设，以及假设不成立时会发生什么。
   区分现成部件、新实现、新证明和未知条件；预算未知时不宣称可行。
4. 提出最重要的竞争解释，例如收益来自更多参数、额外数据、预算差异、测量定义或信息泄漏。
   从机制与竞争解释各自推出预测；说明哪些观察双方都能解释，哪些观察能把它们分开。
5. 将预测落成最小区分性实验：对照改变哪一个因素、哪些条件保持一致、独立结局是什么。
   总性能提升不能单独证明机制；明确支持、削弱或否定原解释的观察，及失效时的论断边界。
6. 核查问题、机制及其替代术语，结合经典来源与近期原始论文，深读最近邻工作的相关正文。
   按 [文献核查规则](02-novelty.md) 记录已有能力、真实差异和定位；未知时保留 `insufficient_search`，不宣称新颖。
   文献核查服务于当前问题和解法；若发现重合，先修订机制或论断边界，不自动重开选题。
7. 再按需查看 [创新模式](patterns.md) 和 [贡献审查](contribution-rubrics.md)，只用能解释真实研究操作的部分，允许不匹配任何模式。

机制不直观时，按 [讲解与交付](explanatory-delivery.md) 用一个小实例对照合理基线，列出关键中间量与失效情形。示意计算只说明操作，不替代独立任务结局。

默认深化一个解法；用户要求比较时，给少量有实质差异的机制，并比较假设、预测与代价，不展开大量新题目。
科学解释和区分预测明确后，再依据当年官方 scope/track/reviewer guidelines 讨论会议适配，不套用会议刻板偏好。

按 [研究 Tips](review-tips.md) 核对实质贡献与部件分工。方法或模式名称不是贡献；组合要说明各自解决什么问题，有交互主张时才要求对应证据。

## 判定与交接
继续设计：机制具体，关键假设可核查，至少一个实验能区分核心解释与主要竞争解释。
需修改：解法有操作细节，但预测与竞争解释相同，或只有总体性能目标。
需补证据：关键文献、数据条件、技术假设或预算依据不足；构思可以保留为假设，不能升级为已验证贡献。
建议暂缓：明确重合或资源无法支持关键检验；给出依据，由作者决定下一步，不换算录用概率。
将机制、预测、失败边界和最小实验交给 [实验设计](03-experiments.md)；尚未运行的实验始终是计划。

## 输出
交付构思卡：继承的问题、核心操作与作用链、关键假设、主要竞争解释、区分预测、最小验证和资源依据。
按需参考 [构思卡模板](../assets/idea-card.md)，不强制套用字段；检索记录和审查问题可放独立说明。
临时任务直接交付；启用持久化记录且允许写入时再保存附属文件，已有作者选择无需重复批准。
完整人工教学示例见 [从问题到最小计划](../examples/problem-to-plan.md)；它不代表 agent 评测或真实实验结果。

方法来源：S1、S2、S3；阶段边界、竞争解释交接与会议适配为本包设计。
