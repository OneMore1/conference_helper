# 交互与交付

## 先让当前任务可完成

从用户自然语言中提取：本轮要做什么、材料在哪里、修改/执行边界。已有信息不再让用户填写表单。
只读请求包括不更新已有状态或证据账本；局部任务只修改指定范围。用户已明确的研究选择与授权沿用到本轮，只对未覆盖的新动作确认。
先读取直接相关材料；仅当缺失信息会改变当前动作或关键结论时追问。
能在明确假设下完成的部分先完成，将假设写在编辑备忘录或分析说明中。
会改变结果数字、方法事实或授权范围的缺失信息不能用假设代替。

| 情境 | 读取和展示 |
|---|---|
| 只有方向、已有模型或已有结果 | 按 [研究入口](12-research-entrypoints.md) 分别收窄问题、安排消融或组织文章；补充材料仅限会改变当前判断的部分 |
| 明确的局部润色、术语统一 | 目标段落及核对事实所需的相邻材料；一句话定位后交付 |
| 初次接手、用户问下一步、结果发生变化 | 相关材料的小型清单；最多六行阶段卡，再执行当前任务 |
| 连续修改同一产物 | 复用已核查依据，读新增/变化部分；只报告变化 |
| 跨会话继续或多个研究分支 | 读取相关状态与最新材料，核对差异；只更新当前分支 |

一句话示例：“本轮只整理 Methods，依据 protocol.md；结果解释问题记入单独备忘录。”
阶段卡允许合并项目：已有进度、建议下一步、本轮任务、依据、关键缺口、本轮产物。
没有可并行工作或阻断问题时无需硬凑栏目。用户不必知道内部阶段代码。

## 把缺口变成可采取的动作

区分三种影响：阻碍当前任务；只限制某条科学论断；可选改进。
别把所有未完成环节列成当前任务的前置条件。能写清的 Methods 可以先交付。
遇到资料矛盾，给出双方的文件位置和受影响语句；先保留可确定内容。
建议只选一个当前最有价值的下一步，并解释它将解决哪项不确定性。
需要补充时给出最小动作与停止条件；“缩小论断”“保留负结果”“无需新增动作”均可成为结论。

## 让用户知道交付是否可用

交付中先给用户要的成品或文件链接，再给必要的修改摘要与依据。
局部改稿另附简短编辑备忘录；分析给出可核算数值、统计单位与来源；计划与实际运行结果分别标明。
对可计算结果核对输入版本、计算方法及对应行/列。不能把预写示例回复称为实际 agent 评测。
只有启用了持久化工作区且允许写入时才保存状态。临时或只读任务可在收尾给一个短交接段，不强迫创建 JSON；已有分析报告或账本不是局部任务的必备材料。
交接段包含当前任务、材料版本、已完成产物、未决问题和建议下一步；不自动执行下一阶段。
