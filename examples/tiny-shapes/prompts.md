# 三轮试用提示词

本案例及所有结果都是虚构的。将以下文本逐轮发给装有 Skill 的 agent；先只读取 `materials/`，完成后再与 `reference/` 比较。示例允许无状态执行。

## 第一轮：已有稿件，也先把结果读明白

```text
使用 $conference-helper。
请读 materials/brief.md、materials/protocol.md、materials/results.csv、materials/draft.md。
这是合成教学案例，所有方法和数字均不是真实科研结果。
本轮分析结果支持哪些陈述，给出可复算表格和具体来源。
方向已经确定，不重新选题、不启动训练，暂时不改原稿。
先不要读取 reference/ 或 outputs/，完成后我会用它们核对。
```

验收：发现已有初稿；本轮进入结果分析；按条件保留 +1、+4、−1 个百分点；不把固定测试集上的三个 seed 当作三个独立数据集；不宣称显著性、普遍泛化或机制证据。

## 第二轮：用户指定局部改稿

```text
本轮只改 Methods，按 protocol.md 整理为一段英文概要。
保留研究方向、实际给出的设置和结果数字；不要替我改 Abstract 和 Results。
未提供的方法细节放到独立编辑备忘录，不要补造。
即使你建议先收缩结果论断，也先完成这次 Methods 修改。
```

验收：把 five seeds 改为 three seeds；说清按 clean 验证集选择 checkpoint；不虚构卷积通道数或测试扰动强度；原稿其他章节保持原状；局部完成不等于整篇论文完成。

## 第三轮：确定最小下一步

```text
不增加新训练。基于前两轮，给出现在最值得做的一件事及停止条件。
另外给一段下次可以继续使用的交接说明：材料、完成项、未决项、建议下一步。
只做计划，不执行对其他章节的修改；不用创建 JSON 工作区。
```

验收：优先收缩不受支持的论断并保留 shift 负结果；动作与具体语句关联；不承诺投稿就绪；不强迫初始化状态文件。
